# Appendix B — Checklist to Evaluate an AI Vendor

Use this before you sign with any AI vendor. Work through each theme. If a vendor cannot answer a question clearly, treat that as a warning. Write a **Yes / No / Unknown** next to each item. A long list of "Unknown" is itself an answer.

## 1. What the tool actually does

- [ ] The vendor can state, in plain words, the one problem it solves for me.
- [ ] It fits a real process I have, not a vague "it can do everything."
- [ ] I have seen it work on my kind of data, not only a polished demo.
- [ ] I know what it does **not** do, and where it fails.
- [ ] The output is something I can check for correctness.

## 2. Data and privacy

- [ ] I know exactly what data the tool collects and stores.
- [ ] I know where the data is stored (which country / region).
- [ ] My data is **not** used to train the vendor's shared model unless I agree in writing.
- [ ] I can delete my data and get proof of deletion.
- [ ] The vendor explains how it handles personal and sensitive data.
- [ ] Data is encrypted both while stored and while moving.

## 3. Security

- [ ] The tool supports strong login (multi-factor authentication).
- [ ] Access is controlled per person, so not everyone sees everything.
- [ ] There is a log of who did what, that I can review.
- [ ] The vendor has a written security policy I can read.
- [ ] The vendor tells me about breaches promptly (a clear notification promise).
- [ ] I know how they protect against common attacks (for example, prompt injection in tools that read outside text).

## 4. Compliance (GDPR and EU AI Act)

- [ ] The vendor can say how it complies with GDPR.
- [ ] If my use is higher-risk under the EU AI Act, the vendor supports the extra duties (records, human oversight, transparency).
- [ ] They offer a data-processing agreement (the standard contract GDPR asks for).
- [ ] They can support a DPIA if my project needs one.
- [ ] They tell me if they use any sub-processors (other companies handling my data).

## 5. Pricing

- [ ] The price is clear, with no hidden extras.
- [ ] I understand how cost grows if usage grows (per user? per task? per message?).
- [ ] I know what happens if I exceed my plan limits.
- [ ] I know the renewal price, not just the intro price.
- [ ] There is a cheaper tier that still meets my core need.

## 6. Support and service

- [ ] There is a real support channel (email, chat, phone) with stated hours.
- [ ] Response times are written down, not promised verbally.
- [ ] There is help to get started (onboarding, guides, training).
- [ ] The tool has a stated uptime commitment (a reliability promise).
- [ ] I can reach a human when it matters.

## 7. Contract and exit

- [ ] I can cancel without a heavy penalty.
- [ ] I can export all my data in a usable format at any time.
- [ ] I know how much notice is needed to cancel.
- [ ] The contract length is reasonable for a first commitment.
- [ ] I have thought about lock-in: how hard is it to leave later?
- [ ] I keep ownership of my own data and content.

## 8. Trust and reputation

- [ ] I have checked references or reviews from businesses like mine.
- [ ] The company has been operating long enough to be accountable.
- [ ] I know who to contact if something goes wrong.
- [ ] Their claims are believable, not exaggerated.

## 9. Trial and proof

- [ ] I can run a small trial before committing.
- [ ] I defined what "success" looks like for the trial.
- [ ] I tested it on my real data, not only sample data.
- [ ] I know the date I will decide: continue, change, or stop.

## Quick scorecard

Add up your answers:

| Result | Meaning |
|--------|---------|
| Mostly **Yes** | Good candidate. Move to a small pilot. |
| Several **No** on data, security, or exit | High risk. Ask more or walk away. |
| Many **Unknown** | The vendor is not transparent. Treat as a red flag. |

**Rule of thumb:** Never trade away control of your data for convenience. If the vendor will not answer plainly, that is your answer.
