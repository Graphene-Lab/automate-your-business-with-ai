# Appendix A — Simple Glossary

Plain-English meanings of the words you will meet in this book. Each entry is short on purpose. If a term is missing, look for the closest word here first.

**AI agent** — Software that does a small job for you on its own, like reading an email, deciding what to do, and taking the next step. Unlike a simple chatbot, it can act across several steps without you guiding each one.

**Algorithm** — A fixed set of steps that solves a problem, like a recipe. A computer follows the steps in order to get a result.

**Anonymization** — Removing everything that can identify a person from data, so no one can be traced back. Done well, the data can no longer be linked to a named person.

**API (Application Programming Interface)** — A connection that lets one piece of software talk to another. It is how an AI tool reads your customer list or writes into your accounting system.

**Artificial intelligence (AI)** — Software that does tasks that normally need human thinking, like reading text, spotting patterns, or answering questions. It is a tool, not a person.

**Bias** — A unfair tilt in a system's results, often because the data it learned from was skewed. For example, a hiring tool trained mostly on one group may favour that group.

**Chatbot** — A program you chat with by typing. It replies to messages. It may use AI, or it may follow simple scripted rules.

**Cloud** — Software and storage that run on someone else's computers over the internet, not on your own machine. You usually pay a monthly fee.

**Data poisoning** — Corrupting the data a system learns from, on purpose, so it behaves badly later. It is an attack on the data, not on the live system.

**Dataset** — A collection of data used to teach or test a system. Think of it as the study material.

**Digital sovereignty** — The ability to keep control of your own data and the systems that use it, instead of handing that control to an outside provider you cannot influence.

**DPIA (Data Protection Impact Assessment)** — A structured check you do before a project, to ask: what could harm people's privacy, and how do we reduce it? Under GDPR it is required when processing is high-risk.

**Encryption** — Scrambling data so that only someone with the right key can read it. It protects data while stored or while moving over the internet.

**EU AI Act** — European rules for AI. It sorts AI uses into risk levels and sets stricter duties on higher-risk ones, like hiring or credit tools.

**GDPR (General Data Protection Regulation)** — European privacy law. It sets rules for handling personal data: collect only what you need, keep it safe, and respect people's rights.

**Generative AI** — AI that creates new content — text, images, or audio — rather than only sorting or scoring. Most chat tools you hear about are generative AI.

**Inversion attack** — A way to try to recover private data from a system by working backwards from what it gives out. It is one reason to limit what a system reveals.

**Integration** — Connecting AI to the tools you already use, so data flows between them without copying by hand.

**KPI (Key Performance Indicator)** — A number you track to see if something is working, like response time or sales per week.

**Large language model (LLM)** — A type of AI trained on huge amounts of text so it can understand and produce human language. It is the engine behind many chat tools.

**Lock-in** — When it becomes hard or costly to leave a provider because your data, settings, or workflows are stuck in their system. Plan your exit before you commit.

**Logging** — Keeping a record of what a system did, and when. Good logs help you find problems and prove what happened.

**Low-code** — Tools that let you build simple automations with a bit of configuration instead of full programming. Some technical skill still helps.

**Machine learning (ML)** — A way to build AI by showing it many examples and letting it find patterns, instead of writing every rule by hand.

**Model** — The "learned thing" produced by training. It is the software that makes predictions or generates text after learning from data.

**No-code** — Tools that let you build automations without writing any code, usually by dragging and clicking.

**Pilot** — A small, limited trial of a new tool or process, run before you commit fully. Its goal is to learn cheaply whether it works.

**Prompt** — The instruction or question you give to an AI tool. A clearer prompt usually gives a better result.

**Prompt injection** — A trick where hidden text in a document or message fools an AI into ignoring your instructions and doing something else. Treat outside text as untrusted.

**Pseudonymization** — Replacing a name or ID with a code, so data is harder to link to a person, but can still be re-linked with a key. It is safer than plain data, but not the same as full anonymization.

**ROI (Return on Investment)** — How much value you get back compared to what you spent. A simple way to judge if a project paid off.

**RPA (Robotic Process Automation)** — Software that repeats a computer task by mimicking a person clicking and typing. Good for boring, rule-based work.

**Self-hosting** — Running software on your own computers, instead of on a provider's cloud. You keep more control, but you carry more work and risk.

**Shadow AI** — AI tools that staff use without the company's knowledge or approval. Convenient, but a hidden risk to data and compliance.

**Training** — The process of teaching a system by showing it many examples so it learns patterns. It happens before the tool is used in real work.

**Trustless** — A design where you do not have to blindly trust the other side. Control and checks replace trust. You verify instead of hoping.

**Virtual assistant** — An AI helper you talk to by voice or text, like a digital secretary. It can answer questions, set reminders, or draft messages.
